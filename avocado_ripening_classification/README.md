A reproducible computer-vision project for GreenPod Labs Assignment 2. It compares **classical color/texture features + machine learning** with **MobileNetV2 transfer learning** for four avocado ripening stages.

> **Important integrity note:** This repository scaffold does not claim to contain trained weights or measured accuracy. The dataset must be downloaded and training executed locally or in Colab. Metrics, plots, and weights are generated by the pipeline; do not submit example or invented numbers as experimental results.

## Problem statement
Classify an image into `underripe`, `breaking`, `ripe`, or `overripe`. The intended use is produce-sorting assistance, not a definitive internal-firmness or food-safety test.

## Approaches
1. **Classical CV + ML:** RGB/HSV/LAB histograms, LAB channel statistics, Local Binary Patterns (LBP), GLCM texture descriptors; tuned SVM and Random Forest with stratified cross-validation.
2. **Deep learning:** ImageNet-pretrained MobileNetV2, frozen feature backbone and custom dropout/LayerNorm classifier head, augmentation, Adam, cross-entropy, ReduceLROnPlateau, early stopping.

## Dataset
Assignment Google Drive: [Avocado dataset](https://drive.google.com/file/d/1NMJ0FOxcWH1mwFFeERuY6fgEY-MVgeET/view). **The linked archive audited on 2026-10-26 contains disease labels (`blackspot`, `canker`, `fresh`, `grenning`), not ripeness labels. Do not use it to train or report ripeness performance; obtain the correct four-stage dataset first.** Use only data you are permitted to access. Expected directory layout:

```text
data/raw/
├── underripe/   # or hard/
├── breaking/    # or firm/
├── ripe/        # or soft/
└── overripe/    # or decay/
```

The loader recognizes common aliases. Extract data into `data/raw/` only after confirming its class folders represent the four ripeness stages above; the currently configured Drive archive does not.

## Run EDA
```bash
jupyter notebook notebooks/01_EDA.ipynb
```
The EDA notebook records class counts, image dimensions, corrupt files, brightness/color statistics, sample grids, and potential outliers. These checks flag candidates for human review; they do not automatically prove that an image is mislabeled.

## Train both approaches
```bash
python train.py --data data/raw --epochs 15
```
This creates the split manifest, tuned SVM/RF bundles, MobileNetV2 checkpoint,
per-model metrics, confusion matrices, ROC curves (when all classes are represented),
and a comparison CSV. On first run MobileNetV2 may download pretrained ImageNet
weights. If compute is limited:
```bash
python train.py --skip-dl
```
This is useful for debugging only; **submission must train and report both approaches**.
For offline development, `python train.py --no-pretrained` avoids the ImageNet
weight download, but the resulting model is not an ImageNet transfer-learning run.
The default `--num-workers 0` is intentional for Windows and notebook compatibility.

## Demo inference
```bash
python main.py --image data/raw/ripe/example.jpg
```
It prints SVM, RF, and MobileNetV2 predictions when corresponding model artifacts exist, saves the available predictions as JSON under `outputs/predictions/`, and displays the image with predictions. Pass `--output path/to/prediction.json` to choose a different JSON path. Missing model files are reported rather than silently substituted. Classical probabilities are confidence scores from the fitted estimators, not guaranteed calibrated probabilities.

## Evaluation protocol
- Split: stratified 70% train / 15% validation / 15% test, seed 42.
- Hyperparameter selection: stratified CV using macro F1 on training data.
- Candidate model/epoch selection: validation macro F1 (MobileNetV2 epoch checkpoints are selected by validation loss).
- Final report: held-out test accuracy, macro precision, macro recall, macro and weighted F1, per-class classification report, confusion matrices, and one-vs-rest ROC curves/AUC when valid probabilities and all classes are available.
- The test set is not used to select a model. Compare test scores only after selection is complete; repeatedly choosing the highest test score would leak test information into model selection.
- The split manifest records the exact split. Identical byte-level files are deduplicated before splitting. Near-duplicates or multiple captures of the same fruit require capture/session metadata and a group-based split.
- If a class has fewer than six unique readable images, the requested stratified 70/15/15 split is not viable and training stops with an explanation.

## Known limitations
- Visible skin color is only a proxy for internal softness and can vary by cultivar.
- A single view can miss bruises or decay on the far side.
- Adjacent ripening labels can be subjective and overlap.
- Dataset source, class distribution, background, and lighting may bias results.
- Production use requires calibration, representative validation data, drift monitoring, and a safe fallback/manual inspection path.

## Future work

## Artifact trust and security
Only load model files generated by this project or otherwise trusted. Classical `.joblib`
files use Python object serialization and can execute code when loaded. The PyTorch
checkpoint loader uses PyTorch's restricted weights-only loading mode. Dependency
versions in `requirements.txt` are compatibility ranges, not a completed vulnerability
scan; review current advisories before deployment.

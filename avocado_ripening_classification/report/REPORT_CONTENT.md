## 4. Data Cleaning and Preprocessing
Images that cannot be decoded are logged for review. Classical features use a consistent 128×128 image representation and optional mild denoising. MobileNetV2 inputs are resized to 224×224 and normalized with ImageNet channel statistics. Augmentation is applied only to training images. Validation and test images are not augmented.

Splitting is stratified into approximately 70% train, 15% validation, and 15% test using seed 42. Exact byte-identical files are removed before splitting. For multiple views of the same fruit, or near-duplicates, split by fruit/session/group rather than randomly to prevent leakage; this requires capture/session metadata not supplied by this project.

## 7. Approach 1: Classical CV + Machine Learning
RGB, HSV, and LAB channel histograms summarize color distributions. LAB a-channel statistics help characterize green-to-red color variation but are not sufficient alone to determine ripeness. Local Binary Patterns capture local texture, and GLCM properties describe contrast, homogeneity, energy, correlation, and angular second moment. The combined vector is evaluated with:
- SVM (RBF kernel; tuned C and gamma, standardized features)
- Random Forest (tuned tree count, depth and leaf size)

Hyperparameters are selected by stratified cross-validation on the training data using macro F1. Candidate models are selected using validation macro F1; test metrics are held back for final reporting after selection is fixed.

## 8. Approach 2: MobileNetV2 Transfer Learning
MobileNetV2 uses ImageNet pretrained visual representations. The feature backbone is frozen initially, and a new classifier head includes dropout, linear layers, LayerNorm, and ReLU. Training uses class-weighted cross-entropy, Adam, rotation/translation/flip/color augmentation, a validation-loss learning-rate scheduler, and early stopping. Save the best validation-loss checkpoint and evaluate it once on the test set.

## 9. Evaluation Metrics
- **Accuracy:** fraction of all test examples classified correctly; can hide poor minority-class performance.
- **Macro precision:** average precision across classes, measuring reliability of positive predictions for each class.
- **Macro recall:** average sensitivity across classes; important when missing a ripe/overripe stage is costly.
- **Macro F1:** harmonic mean of precision and recall, averaged equally across classes; primary selection metric when classes may be imbalanced.
- **Weighted F1:** class F1 averaged by true class support; included to complement macro F1.
- **Confusion matrix:** reveals which adjacent stages are confused.
- **ROC-AUC OVR and curves:** probability-ranking metrics when valid class probabilities and all evaluation classes are present.

## 12. Production Considerations (Mandatory Q1)
**How does the model perform in production?** Performance must be measured on representative target hardware and real conveyor conditions; no production accuracy or latency can be asserted before benchmarking. MobileNetV2 is designed to be lightweight, but throughput depends on hardware, preprocessing, image resolution, batch size, and transfer overhead. Measure warmed-up single-image and batch latency on CPU/GPU/edge hardware. Scalability can be achieved with a queue-based inference service and batching, but production requires camera calibration, consistent illumination, drift monitoring, logging, and human/manual fallback. Environmental shifts such as glare, shadows, wet skin, cultivar variation, and background changes may reduce accuracy. Real-time suitability is a measured service-level requirement, not assumed from architecture alone. Energy impact should be estimated by measuring device power and processing throughput; edge inference may reduce network transfer but is not automatically lower-carbon.

## 13. Drawbacks (Mandatory Q2)
- **Color ambiguity:** skin color does not always reflect internal softness; some cultivars remain green when ripe.
- **Single view:** one camera may miss localized bruises or defects on the far side.
- **Class overlap:** breaking and ripe stages form a continuous transition and labels can be subjective.
- **Dataset bias:** limited varieties, lighting, backgrounds, and cameras may not represent production conditions.
- **Label noise:** incorrect or inconsistent stage annotations cap achievable performance.
- **Feature/model limitations:** classical color-texture features can be sensitive to lighting, while a CNN can learn spurious background cues and may be overconfident.
